# RC check script Implementation Plan

**Goal:** `scripts/rc_check.py` with `sandbox`, `upgrade` and `rollback`, and docs/release.md
section 4 rewritten around it.

**Architecture:** One standard-library script in `scripts/`, run as `python3
scripts/rc_check.py` from the repository's root. Every external command goes through one
runner function the tests replace; every sandbox command gets its environment from one
function. CHANGELOG items come through `release_notes.section`.

**Tech Stack:** Python 3.10+ standard library (`argparse`, `subprocess`, `sqlite3`,
`tempfile`, `urllib.request`, `json`, `shutil`), pytest.

**Spec:** `docs/superpowers/specs/2026-10-14-rc-check-design.md`,
`openspec/changes/rc-check-script/` (design.md D1-D11, delta `release-candidates`).

## Global Constraints

- Standard library only; `from __future__ import annotations`; no import of `lado`.
- Every LADO process of the sandbox: `LADO_TELEMETRY=0`, `LADO_HOME`, `LADO_TMUX_SOCKET`,
  `UV_TOOL_DIR`, `UV_TOOL_BIN_DIR` inside the sandbox folder; never the human's home.
- `upgrade` and `rollback` never pass `--yes` to `lado update`; `rollback` asks
  `Roll back? [y/N]` itself and refuses without a terminal.
- Output English; check lines `[ok  ] <what>` / `[FAIL] <what>: <reason>`; exit 0 / 1 / 2
  (usage, and a final as the default version), 130 on Ctrl-C.
- The kept copy: `~/.lado-rc/lado.db.<final>`, at most one file there.
- Commit messages: a plain sentence ending in `(LAD-51)`.

## Review Focus

- `lado` on PATH is the working copy's `.venv/bin/lado` (run under `uv run`): `upgrade`
  and `rollback` must refuse, naming it (Task 3 test).
- A sandbox check fails after the session started: the kept sandbox has a tmux server
  running; the printed cleanup command must end it (Task 2 test of the printed line).
- `rollback` when the human answers `n` at `lado update`'s own question: nothing restored,
  no session started on the RC's binary silently; the script says the rollback stopped
  and how to resume the sessions (Task 4 test).
- `rollback` when a session's repo no longer exists: that `lado start` fails, its
  `[FAIL]` line, the others still start (Task 4 test).
- PyPI unreachable: one `[FAIL] PyPI: <reason>` line, exit 1, no folder made (Task 1
  test).
