# LADO 0.49.0: the release's checks

The last final is 0.48.0. The database's schema moves from 43 to 44 (LADO's commit author and
a project's), so 4.2, 4.4 (with the user's own way back) and 4.6 of docs/release.md all hold.
The image changed (`docker/compose.yaml`'s header and `LADO_GUIDE`, the entrypoint's warning
about git's identity), `docker/install.sh` and `docker/install.ps1` did not, so 4.5 runs
without its installers. Those checks of every RC are not repeated here; this file holds what
0.49.0 itself needs: the commit authors (LADO's, a project's, a server's) on your own LADO and
on a fresh one whose git knows nobody, in Docker without `LADO_GIT_NAME`, the CLI's lines when
nobody is left to sign, the first-run guide with its tips, Not now, Help → Getting started and
`LADO_GUIDE=0`, the faster first turn, the end of Model servers and Git servers in Safari and
Firefox, and what going back to 0.48.0 loses.

## 0.49.0rc1

The RC: tag `v0.49.0rc1`; its commit and its `live.yml` run go here once made. The exact
lines below are the code's; where the code has no fixed text, the line says what to look for.
Test authors below are made up (`RC Lado <rc-lado@example.com>` and the like): remove each one
where its check says so.

### Before you start

- A Mac with your LADO 0.48.0 and sessions running, Docker Desktop, `uv`, `tmux`, git 2.36 or
  newer (`git --version`; LADO's or a project's author needs 2.31, a server's 2.36).
- Your own git author noted: `git config --global user.name` and `user.email`. No check here
  changes them; compare at the end.
- A small test repository of your own on github.com (saved in Settings → Git servers since
  0.48.0), and a local one without a remote.
- An OpenRouter key (or another model server's) for the guide's path on a fresh home: there
  no agent CLI is logged in.
- Safari and Firefox on the Mac.

### Your own LADO after the upgrade (4.2)

- [ ] **The schema moves to 44.** 4.2's `upgrade` prints the migration and keeps the copy.
  - `lado: upgraded lado.db from schema 43 to 44; its backup is
    /Users/<you>/.lado/backups/lado.db.schema-43`, and `Kept a copy of LADO 0.48.0's
    database: /Users/<you>/.lado-rc/lado.db.0.48.0 (for rollback)`.
- [ ] **No guide on your LADO, the tips once.** Open the UI after the upgrade, then New session.
  - No "Welcome to LADO": your agent CLIs are logged in, so the guide's record is made
    completed.
  - New session shows one tip, `Describe the task here in your own words. …`; Got it closes
    it, and it does not come back at the next opening nor after a reload.
- [ ] **Your commit author is as before.** Settings → Git servers, `lado git-server author`, `lado doctor`.
  - Above the servers, the block Commit author: the row LADO's author reads `<you> <<email>>
    · from git on this computer` with `Set author`.
  - `lado git-server author`: `LADO has no commit author: agents commit as <you> <<email>>
    from your git config.`; `lado git-server list` starts with `LADO's commit author: -`.
  - `lado doctor`: `[ok  ] git author: user.name and user.email set`.
  - A resumed agent's commit carries your git author, as on 0.48.0.

  - `git config --global user.name` and `user.email` print your own, unchanged.
- [ ] **A server's author wins over LADO's.** github.com's row → Commit author → `RC Server` and `rc-server@example.com`; a session on the github.com test repository; the agent commits.
  - Before, github.com's panel reads `Commit author: RC Lado <rc-lado@example.com> (LADO's) ·

### A fresh LADO whose git knows nobody

In a fresh terminal, a test home with no git author (the Mac's system git config has none;
`git config user.name` must print nothing):

```
export T=$(mktemp -d)
export HOME=$T LADO_HOME=$T/.lado LADO_TMUX_SOCKET=lado-rc-fresh LADO_TELEMETRY=0
export LADO_AGENT_ENV=inherit PATH=$T/.local/bin:$PATH
git config user.name; git config user.email
uv tool install lado==0.49.0rc1
```

- [ ] **`lado doctor` and the CLI say nobody signs.** `lado doctor`, `lado git-server author`.
  - `[warn] git author: no LADO commit author and no user.name or user.email: agents cannot
    commit`, with the `lado git-server author` command.
  - `LADO has no commit author and git knows none: agents cannot commit.` and `Set one in
    Settings → Git servers, or run: lado git-server author --name "Your Name" --email
    you@example.com`.
- [ ] **A fresh start is refused, nothing made.** `lado start --new $T/workspace/coffee`.
  - `nobody signs the agents' commits: LADO has no commit author and git has no user.name or
    user.email`, then `Set the commit author in Settings → Git servers, or run:` and the
    command; `ls $T/workspace` has no `coffee`.
- [ ] **The guide's whole path.** `lado ui --port 8798`; answer the statistics question if it shows.
  - "Welcome to LADO" in the middle with Show me and Not now, and `You can start the guide
    again from Help → Getting started.`
  - Show me: `Open Settings`, then the rows of Agent CLIs; `I have neither` on each passes on
    to Model servers (`An OpenRouter key, or a model on your computer?`). Its `I have none of
    these — what should I choose?` opens the card `Don't have any of these yet?`; Back
    returns.
  - A press on the dimmed page outside the ring does nothing; the step stays.
  - Add server with the OpenRouter key: `Choose a model`, then `Tick the agent CLIs that run
    it`; after the first tick `✓ Model saved — agents check it when they start` and `Sign the
    agents' work` (`Sign your work · Step 2 of 3`). A reload here keeps `Step 2 of 3`.
  - Git servers: `Who signs the work?` at the row reading `⚠ Nobody: agents cannot commit`,
    `Your name and email` at the form; Save author: `✓ Your work will be signed` and `Start
    your first session` (`Start working · Step 3 of 3`).
  - New session: the guide closes and the New session window's tip shows.
- [ ] **The first session starts and is signed.** In that window, New empty folder `coffee`, the agent the ticked model runs, a task; Start.
  - The session starts; `git -C $T/workspace/coffee log -1 --format='%an <%ae>'` prints the
    author saved in the guide; `git config --global user.name` still prints nothing.
- [ ] **Each tip once.** In that session: the session page, an agent's terminal, and ask the supervisor to ask you a question with choices.
  - `This is your session. …` under the tabs, `This is the agent's own window. …` at the
    terminal's bar, `An agent asks you something. …` at the question card; one at a time,
    each until Got it, none again in another session or after a reload.
  - Don't show tips like this on one: no tip shows after it, in Firefox too (the same LADO).
  - The gate's tip (`The team waits for your decision. …`) needs a flow: the browser test
    covers it.
- [ ] **Help → Getting started and Not now.** Help on the rail → Getting started; then Not now; reload.
  - The welcome says `A model and an author are set up already. This guide shows how to
    start your first session.`; Show me leads straight to New session.
  - After Not now and a reload no guide shows, in Firefox neither; Esc on a guide's card does
    as Not now and puts the focus back where it was.
- [ ] **The guide on a phone's width.** Safari → Develop → Enter Responsive Design Mode, an iPhone's 390 px, Help → Getting started, Show me.
  - `Open the menu` rings ☰ whole on screen, its card below it; then `Open Settings`.
- [ ] **New session without an author.** Remove LADO's author on Git servers, then New session → New empty folder.
  - The note `Agents need a name and email to sign their commits, and none is set yet.` with
    `Set it in Settings ↗` and `Check again`; the footer `To start: set the commit author`.
  - Check again: `Checked again: still nobody. Save the name and email in Settings first.`
  - Set it in Settings ↗ opens a tab with LADO's author form open, Name focused; Save
    author: `✓ Author saved. Go back to the New session tab: it checks again by itself.` Back

  - Projects → a new project → Add repository → From scratch shows the same note while
    nobody signs, Create off.
- [ ] **Clearing the last author says agents cannot commit.** On the fresh home, LADO's author set: `lado git-server author --clear`, then a project's author set and cleared.
  - `lado git-server author --clear`: `LADO has no commit author now.`, the two lines of
    nobody above, and `Running agents keep the author they started with until they
    restart.`; no line says agents commit.
  - `lado project create shop`, `lado project author shop --name "Shop Bot" --email
    bot@shop.example`: `Agents of project shop commit as Shop Bot <bot@shop.example>.` and
    `Agents started from now on commit so; restart running agents to give it to them.`
  - `lado project repo add shop --new site`, then `lado project author shop --clear`:
    `Project shop has no commit author now, and nobody else signs its agents' commits: they
    cannot commit.`, `Set one: lado project author shop --name "Your Name" --email
    you@example.com, or LADO's in Settings → Git servers.` and the running agents' line.
  - `lado project author shop`: `Project shop has no commit author, and nobody else signs
    its agents' commits: they cannot commit.` and the same hint.
- [ ] **`LADO_GUIDE=0` keeps it away.** `lado server stop`, a new `LADO_HOME=$T/.lado2`, `LADO_GUIDE=0 lado ui --port 8798`.

    started, which shows the welcome; after a reload nothing starts by itself.

Then remove it all and close the terminal:

```
lado server stop; LADO_HOME=$T/.lado lado server stop; LADO_HOME=$T/.lado lado stop --all
tmux -L lado-rc-fresh kill-server
rm -rf "$T"
```

### Agents start sooner

Nothing a human sees tells a third of a second; what shows is the cache and that nothing
else changed.

- [ ] **The first turn's tools come from a cache.** On your own LADO after 4.2, start a session, then a second one of the same kind.
  - `ls ~/.lado/mcp-cache/` lists a few JSON files after the first start.
  - The second session's supervisor answers its first message in the chat as before, and
    its LADO tools work (a question card, a message).
  - `grep -c mcp:cache ~/.lado/errors.jsonl` prints `0` (or the file is missing): no cached
    answer was contradicted.
- [ ] **A worker gets its own tools.** In a session with a kit's worker, the worker's first turn uses its tools (send_message to the supervisor) as before.

### Going back to 0.48.0

Going back to 0.48.0 loses everything recorded on the RC: sessions, runs, gates, messages,
projects, model servers, models, default models and git servers made or changed since 4.2's
upgrade, and with them LADO's commit author and the projects' authors, which only lado.db
holds. Agents then commit as git's own author again. The guide's record
(`~/.lado/guide.json`) and the MCP cache (`~/.lado/mcp-cache/`) stay on disk, unused by
0.48.0.

- [ ] **The rollback's plan and warning name what is lost.** 4.4's `rollback`, with LADO's author set on the RC: read its plan before `Roll back? [y/N]`, then `lado update 0.48.0`'s warning before `y`.
  - The plan names the sessions started on the RC after `- not started again, not in the
    copy:`.
  - `lado: WARNING: LADO 0.48.0 knows lado.db up to schema 43; lado.db has schema 44.` and
    `… Everything LADO recorded since then is lost: sessions, runs, gates, messages,
    projects, model servers, models, default models, git servers.` The commit authors are
    lost too, and the warning does not name them: note it as found.
- [ ] **0.48.0 starts on the database of before.** After the rollback.
  - `Restored lado.db from …/lado.db.schema-43 (schema 43)`; `lado ls` lists the sessions of
    before 4.2; Settings → Git servers has no Commit author block, and an agent's commit
    carries your git author.
- [ ] **The user's way back from a LADO author.** 4.4's user's own way back, on its test home, with `lado git-server author --name "RC Lado" --email rc-lado@example.com` run on the RC before `lado update 0.48.0`.
  - The update warns as above; on 0.48.0 `lado ls` lists `back`; 0.48.0 has no LADO author
    (its `lado git-server author` needs an address).
