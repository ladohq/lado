Изоляция сессий LADO: планируемая схема

Устарело в одном месте: прокси ключей и git теперь живёт в runner (ключи runner получает от пульта на время сессии), а не в пульте. Актуальные схемы: артефакт lado-topologies.html.

Черновик по итогам исследования и спайков gVisor. Пульт управления (lado) отдельно, сессии в песочницах gVisor внутри runner. Один compose на macOS, Windows и Linux.

Что изолировано

  • Сессии друг от друга: процессы, файлы, сеть (gVisor, свой netns, iptables).
  • Ключи и токены: только в lado; песочница их не видит, прокси подставляет.
  • Хост: на Mac и Windows ещё и VM Docker Desktop.

Что нужно сделать в LADO

  • Agent API: MCP и хуки по сети с токеном агента (этап B cloud workers).
  • Прокси ключей и git с проверкой репозитория и ветки.
  • Агент runner: песочницы, netns, терминалы.
  • Репозитории сессий на volume, результат через git.

Открыто

  • Где живут репозитории пользователя (volume, bind или синхронизация).
  • Linux: AppArmor, платформа kvm, micro-VM для сравнения.
  • Windows: скорость папок, KVM в WSL2.
  • Один runner на всех или runner на клиента.
